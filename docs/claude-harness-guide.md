# Claude Code 하네스 세팅 가이드

> **출처**: [클로드 코드로 100% 자동화 마케팅 에이전트 팀을 만드는 방법](https://www.youtube.com/watch?v=6MJ-pmckowQ) — 조슈아 (AX 에이전시)
> **정리일**: 2026-05-13
> **목적**: Claude Code를 단순 코딩 어시스턴트가 아니라 "일관된 고품질 결과물을 내는 작업팀"으로 운영하기 위한 환경 세팅 방법론. today-meal 프로젝트에도 적용 가능.

---

## 핵심 철학

> **"실행 5%, 하네스 세팅 95%"**

Claude의 결과물 품질은 프롬프트 한 줄이 아니라 **사전에 깔아둔 환경**(컨텍스트·템플릿·SOP·스킬·서브에이전트)이 좌우한다. 세팅에 시간을 충분히 쓰지 않으면:
- 매번 다른 톤·스타일의 결과물
- 토큰 낭비 (같은 맥락 매번 재학습)
- 일관성 없는 작업 흐름
- 결국 사람이 더 많이 개입하게 됨

세팅을 잘 해두면 **"마케팅 캠페인 전체를 만들어줘"** 같은 한 줄 명령으로 카드뉴스·PPT·뉴스레터·썸네일까지 일관성 있게 산출 가능.

## 7단계 하네스 세팅 프로세스

### 1단계 — 폴더 구조 세팅

프로젝트 루트에 다음 구조를 만든다:

```
project-root/
├── context/        # 회사·프로젝트 맥락 (MD 파일)
├── templates/      # 디자인·문서 템플릿 (이미지 + MD)
├── output/         # 모든 산출물 저장 위치
├── .claude/
│   ├── agents/     # 서브에이전트 정의 (MD)
│   └── settings.json
├── .env            # API 키 (.gitignore 필수)
└── CLAUDE.md       # 표준 업무 규약 (SOP)
```

**원칙**:
- 영문 폴더명 사용 (한글도 동작하지만 호환성/검색성 이점)
- `output/`은 항상 분리해서 산출물과 소스를 섞지 않는다
- `.env`는 git에 절대 올리지 않는다 (`.gitignore` 즉시 추가)

---

### 2단계 — 컨텍스트 문서 작성 (`context/`)

회사·프로젝트의 "맥락"을 MD 파일로 박제한다. Claude는 MD를 가장 잘 읽는다.

**필수 3종**:
1. **`brand-guidelines.md`** — 브랜드 가치, 보이스/톤, 카피라이팅 키워드
2. **`business-context.md`** — 타깃 고객, 페인포인트, 서비스 라인, 차별점
3. **`design-style-guide.md`** — 타이포그래피, 컬러, 컴포넌트 원칙

**문서가 없는 경우의 생성법** (영상의 실제 사용 예):
```
1. 회사 웹사이트(또는 레퍼런스) 스크린샷을 캡처
2. Claude에 첨부하며 명령:
   "이 웹사이트 스크린샷은 [회사명]의 사이트야.
    이 내용을 파악하고 우리 회사의
    브랜드 가이드라인, 디자인 스타일 가이드, 비즈니스 맥락
    세 가지 파일을 마크다운 파일로 만들어줘.
    그 파일들은 context/ 폴더에 생성해줘."
```

Claude가 이미지를 분석해 톤·색·키워드·타깃 등을 자동 추출.

**왜 MD인가?**
- AI는 MD 구조(헤더·리스트·표)를 가장 효율적으로 파싱
- 사람도 읽기 쉬워 유지보수 ↑
- diff 가능 (git 친화적)

---

### 3단계 — 템플릿/레퍼런스 수집 (`templates/`)

산출물의 시각적·구조적 일관성을 위한 참조 자산.

**수집 대상 (영상 기준)**:
- 카드뉴스 레퍼런스 (Pinterest 등에서)
- PPT 슬라이드 레퍼런스
- 유튜브 썸네일 템플릿 (Figma 디자인 export)
- 뉴스레터 형식 (실제 뉴스레터 URL을 Claude에 던지면 구조 추출)

**핵심 트릭 — 이미지를 MD로 변환** ⭐

이미지를 매번 첨부하면 **매번 토큰을 소모**한다. 대신 한 번만 분석시켜 MD로 박제:

```
@templates/card-news-ref.png
이 이미지를 바탕으로 카드뉴스 템플릿 마크다운 파일을 만들어줘.
항상 참조할 수 있는 형태로.
```

결과: `templates/card-news-template.md` — 이후 작업은 이 MD만 읽음. 토큰 절감 + 일관성 확보.

뉴스레터 같은 텍스트 자산도 동일:
```
[뉴스레터 URL]
이 내용 참고해서 뉴스레터 형식 템플릿으로
templates/ 폴더에 MD 파일로 저장해줘.
```

---

### 4단계 — `CLAUDE.md` 작성 (SOP)

> **이게 가장 중요하다.** 프로젝트 운영의 표준 업무 규약.

#### 무엇을 담는가

- 프로젝트 개요
- 폴더 구조 + 각 폴더 용도
- 작업 흐름(어떤 요청 → 어떤 에이전트/스킬 호출)
- 결과물 저장 규칙 (`output/`에 저장 등)
- 브랜드·디자인 핵심 요약 (`context/` 문서로의 링크 포함)
- 절대 하지 말아야 할 것 (negative rules)

#### 생성 방법

폴더와 컨텍스트가 갖춰진 후, Claude에게 직접 명령:

```
CLAUDE.md 파일을 만들자.
전체 프로젝트의 폴더를 스캔해서 맥락을 파악하고,
[프로젝트명]에 걸맞는 파일로 생성해줘.
[무시할 폴더] 폴더는 무시.
```

Claude가 폴더 트리·컨텍스트·템플릿을 모두 스캔해서 자동 작성. 사람이 검토 후 수정.

#### 왜 필수인가

CLAUDE.md가 없으면 매 요청마다 Claude가:
- 모든 폴더를 다시 스캔 (시간·토큰 ↑)
- 일관성 없는 해석 (런마다 결과 다름)
- 사람이 매번 "이건 이렇게, 저건 저렇게" 잔소리해야 함

#### 라우팅 룰

서브에이전트가 생기면 CLAUDE.md에 **라우팅 룰**을 추가:
- 카드뉴스 요청 → `design-agent` 호출
- 리서치 요청 → `research-agent` 호출
- 전체 캠페인 → 4개 에이전트 병렬 가동

> 명시 안 하면 Claude가 매번 자기 마음대로 해석. 이게 일관성 무너지는 원인.

### 5단계 — 스킬 설치

Anthropic 공식 스킬을 설치하면 PPT/PDF/DOCX 같은 표준 포맷을 **정해진 방식**으로 생성. 임의 출력 변형 방지.

#### 설치 절차 (VS Code 확장 기준)

1. Anthropic 공식 스킬 저장소: `https://github.com/anthropics/skills`
2. 저장소 URL 복사
3. Claude Code 확장 → **Plugins → Marketplace** → **Add**
4. URL 붙여넣기 → 마켓플레이스 추가
5. 필요한 스킬 검색 (예: `document`)
6. **Install for this project (locally)** 클릭 → 프로젝트별 적용
7. `.claude/settings.json`에 자동 등록 확인

#### 사용 시점

작업 명령 앞에 **슬래시 + 스킬명**:
```
/pptx 사업 소개서를 만들어줘.
명확하게 우리 템플릿과 컨텍스트가 반영되도록 해줘.
잘 안 되면 CLAUDE.md 업데이트해줘.
```

> "잘 안 되면 CLAUDE.md 업데이트해줘"는 **첫 테스트 단계의 핵심 프롬프트**. 실패를 자동으로 SOP에 반영하게 만드는 트릭.

### 6단계 — MCP 연결 (외부 도구)

Claude가 외부 API와 직접 통신하게 만든다.

#### 예시: Gemini 이미지 생성 MCP (`nano-banana`)

이미지 생성은 Gemini가 강함. Claude는 MCP로 호출만:

1. **MCP 저장소** 찾기 (영상 기준: 한국 개발자 최수민의 `nano-banana MCP`)
2. **설치 명령어 복사** → Claude Code에 붙여넣기
3. **API 키 자리에 본인 키 입력**:
   - Google AI Studio → Get API Key → API 키 만들기
   - 키 복사 → 설치 명령어의 `YOUR_API_KEY` 자리에 교체
4. **승인** → Claude가 MCP 서버 등록
5. **확인**: 다음 세션에서 `/mcp` 입력 → 등록된 MCP 리스트에 표시되어야 정상

> 처음 등록 후 **반드시 Claude Code 재시작** — 안 그러면 인식 안 됨.

#### API 키 보안 원칙

- **절대 외부 노출 금지** (소셜·블로그·동영상)
- `.env` 파일에 저장 + `.gitignore` 추가
- 작업 끝나면 회전(rotate) 권장

#### 무료 vs 유료

Gemini의 경우 무료 등급은 이미지 생성 모델이 Pro 아님. 고품질은 결제 계정 설정 필요.

### 7단계 — 서브에이전트 팀 생성

도메인별 전문 에이전트를 만들어 협업 구조를 세팅.

#### 생성 명령 (영상 기준 프롬프트)

```
클로드 코드의 공식 가이드라인을 따라서
우리 프로젝트에 걸맞는 [도메인] 에이전트 팀 계획도를 제시해줘.
순서는 리서치 → 콘텐츠 제작 → 디자인 → 검수 같은 형식이면 좋겠고,
추천해줬으면 좋겠어.
```

Claude가 4단계 파이프라인 + 각 에이전트의 역할/입력/출력/참조 문서를 제시.

#### 다음 명령 (반드시 이어서)

```
이 구조를 기반으로 에이전트를 만들고,
CLAUDE.md에 라우팅 룰을 추가해줘.
클로드 코드의 공식 서브에이전트 제작 가이드를 따라줘.
```

**"공식 가이드를 따라줘"가 핵심**. 빼면 Claude가 자기 방식으로 만들어 호환성 깨진다.

#### 결과물

`.claude/agents/` 폴더에 에이전트별 MD 파일 생성:
```markdown
---
name: research-agent
description: ...
tools: [WebSearch, Read, Write]
model: sonnet
---

(에이전트의 시스템 프롬프트)
```

#### 개별 테스트

전체 가동 전에 에이전트별로 테스트:
```
@.claude/agents/research-agent.md 를 불러오고
[테스트 주제] 주제로 리서치해줘.
```

각 에이전트가 의도대로 작동하는지 검증. 실패 시 에이전트 정의 수정.

#### 전체 파이프라인 가동

병렬 실행이 가장 강력:
```
[프로젝트] 캠페인을 만들고 싶어.
[필요한 산출물 나열].
[추가 제약사항].

@.claude/agents 폴더의 모든 에이전트 팀을 가동해서 진행시켜줘.
결과물은 output/ 폴더에 저장해줘.
```

영상 기준 실행 시간: 약 10분 (캠페인 전체 산출물 생성).

## 자동화 통합 (선택)

### 예: Buffer API로 소셜 미디어 예약 게시

생성한 콘텐츠를 자동 배포까지.

1. **Buffer 가입** + 소셜 미디어 계정 연결 (LinkedIn, Threads, X 등)
2. **Buffer Developer API** 페이지 접속 → **Access the Beta**
3. **Personal Key 생성** (`Generate Key`) → 키 복사
4. **`.env`에 저장**:
   ```
   BUFFER_API_KEY=xxx
   ```
5. **Claude에 명령**:
   ```
   Buffer API 키를 .env 파일에 저장해놨어.
   예약 포스팅 기능을 테스트해줘.
   [어떤 내용/언제] 예약해줘.
   ```
6. Claude가 라이브러리 설치 + API 호출 + 예약 등록 → Buffer 대시보드에서 확인

## 핵심 운영 원칙 (영상에서 강조)

| 원칙 | 의미 |
|---|---|
| **MD 우선** | 모든 컨텍스트는 MD로. 이미지·URL도 한 번 변환해서 박제 |
| **이미지 → MD 변환** | 매번 이미지 첨부 시 토큰 소모 폭증. 한 번만 분석시켜 MD로 |
| **SOP 명시** | CLAUDE.md가 없으면 매번 다른 해석. 표준 업무 규약 필수 |
| **공식 가이드 따라가기** | 서브에이전트·스킬은 반드시 "공식 가이드 따라줘" 명시 |
| **첫 테스트는 명시적으로** | "잘 안 되면 CLAUDE.md 업데이트해줘" — 실패를 SOP에 자동 반영 |
| **API 키는 `.env`만** | 절대 노출 금지. `.gitignore` 즉시 추가 |
| **결과물은 `output/`** | 산출물과 소스 분리. 일관된 위치 |
| **개별 테스트 → 병렬 가동** | 에이전트 검증 후 전체 파이프라인 실행 |
| **권한은 bypass** | "Bypass permissions" 모드로 매번 묻기 스킵 |

## 결론

영상의 메시지를 한 줄로:

> **Claude를 잘 쓰는 사람과 못 쓰는 사람의 차이는 프롬프트 실력이 아니라 "사전에 깔아둔 환경"의 차이다.**

세팅에 시간을 쓰면 한 줄 명령으로 전체 캠페인을 산출할 수 있다. 세팅을 안 하면 매번 같은 잔소리를 반복하게 된다.
