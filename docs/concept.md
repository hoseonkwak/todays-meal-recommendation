# 오늘의밥 — 컨셉 문서 (v2)

> **마지막 업데이트**: 2026-05-13
> 이 문서는 단일 진실 공급원(Single Source of Truth)입니다. `requirements.md`, `tasks.md`, `design-*.md`는 v1 레거시이며 v2 작업 시 참조하지 않습니다.

---

## 1. 한 줄 정의

**오늘의밥은 5초 안에 끼니를 결정하게 해주는 도구다.**
**결정한 끼니를 한 컷씩 모으면, 한 주를 영상으로 돌려준다.**

- 첫 문장이 **정체성** (1차 가치 — 결정 도구)
- 두 번째 문장이 **잔존 엔진** (2차 가치 — 식사 라이프로깅)
- 마케팅·SEO·홈 헤드라인은 영원히 첫 문장. 둘째 문장은 보너스 메시지.

---

## 2. 컨셉 배경

### v1의 문제

- `Math.random()` 한 줄을 "추천 엔진"이라 부르는 토이 수준
- 차별화 부재 — 동전 던지기와 동일
- 오렌지 + 이모지 폭격으로 신뢰감 약함
- 3단계 로드맵(제휴/예약/계정)은 검증 없이 점프하기엔 갭이 큼
- 점심에만 국한 → 1일 1회 사용, 수익화 천장 낮음

### v2의 입장

> 사람들은 "선택지가 없어서" 메뉴를 못 고르는 게 아니다. **선택지가 너무 많아서** 못 고른다.

따라서 v2는 추천 정확도 경쟁에서 빠지고, **선택의 부담을 분할/제거하는 메커니즘**으로 차별화한다. 그리고 결정한 끼니를 자연스럽게 기록·공유하게 만들어 **사용 빈도와 바이럴 잠재력**을 동시에 확보한다.

## 3. 핵심 가치 (Value Proposition)

| 누구를 위해 | 어떤 문제를 | 어떻게 |
|---|---|---|
| 매 끼니마다 메뉴 고민하는 직장인/학생/자취생 | "지금 뭐 먹지?" 결정 마비 | 컨텍스트 인식 + 선택지 축약 + 강제 결정 메커니즘 |
| 일상을 기록·공유하는 1020 세대 | 식사를 보기 좋게 모아 보고 싶음 | 한 끼 한 컷 → 자동 영상 컴파일 → 인스타 공유 |

**핵심 약속**:
- 진입에서 결정까지 **5초 이내**
- 사용 빈도 **1일 2~3회** (아침/점심/저녁/야식)
- 영상 컴파일은 **1탭 공유 가능한 결과물** 출력

## 4. 사용 시나리오 (시간대별)

진입 시 현재 시각을 자동 인식하여 헤드라인과 메뉴 풀의 무게중심을 시간대에 맞춰 조정한다.

| 시간대 | 헤드라인 | 메뉴 풀 무게중심 | 추천 모드 디폴트 |
|---|---|---|---|
| 06~10시 | "아침 뭐 먹지?" | 죽, 토스트, 시리얼, 샌드위치, 해장 | Quick (시간 급함) |
| 11~14시 | "점심 뭐 먹지?" | 한식·일식·중식·양식 정찬 | Quick / Tournament |
| 17~21시 | "저녁 뭐 먹지?" | 정찬 + 회식/술안주 | Tournament / Slot (여유) |
| 22시~02시 | "야식 뭐 먹지?" | 치킨, 라면, 떡볶이, 족발 | Quick / Slot |

주말은 `브런치`(10~14시) 시나리오 추가. 회식·다이어트 모드는 v2.2+에서 검토.

## 5. 결정 모드 (3종)

기존 v1의 단일 모드 대신 **세 가지 결정 모드**를 제공한다. 첫 진입 시 모드 선택, 설정에서 기본값 지정 가능. 시간대에 따라 디폴트 추천이 달라질 수 있음.

### Mode 1: Quick — 단일 추천 (속도 최우선)

- 진입 즉시 1개 메뉴 추천
- `[좋아요]` `[이거 말고]` 두 버튼
- "이거 말고" 5회까지만 허용 → 6회째는 "주사위 모드"(강제 결정) 안내
- 가장 빠른 의사결정 경로

### Mode 2: Tournament — 3-to-1 토너먼트 (선택의 부담 분할)

- 후보 3개 제시
- 라운드 1: A vs B → 승자 선택
- 라운드 2: 라운드 1 승자 vs C → 최종 확정
- Hick's Law: 둘 중 하나는 부담이 가장 적음

### Mode 3: Slot — 슬롯머신 (재미/운명에 맡기기)

- 메뉴들이 세로로 빠르게 스크롤
- `[멈춤]` 탭 → 멈춘 위치가 오늘의 메뉴
- 컨텍스트 가중치 적용된 풀에서 추출 (완전 랜덤 아님)
- 차별화 요소 + 결정의 책임을 "운"으로 외부화

**모드 공통**:
- 결과 화면에 1탭 피드백(`먹음` / `패스`)
- 카테고리 사전 필터 (선택사항)
- 추천 풀은 시간대 컨텍스트 가중치 적용된 동일한 후보군 사용

## 6. 추천 로직 (모든 모드 공통)

```
candidates = menus
  ├─ filter: 사용자가 선택한 카테고리 (선택사항)
  ├─ exclude: 최근 N일(기본 3일) 먹은 메뉴
  ├─ exclude: 사용자가 "싫어요" 등록한 메뉴
  └─ weight by:
      ├─ time of day  (아침/점심/저녁/야식 적합도)
      ├─ day of week  (월~금 vs 주말)
      ├─ weather      (옵션, 위치 권한 허용 시)
      ├─ user history (자주 "좋아요" 한 카테고리 +α)
      └─ photo signal (사진 캡처한 메뉴는 만족도 신호로 가중)
```

**핵심 원칙**:
- 가중치는 0.5x ~ 2x 범위에서만 작동 (편향 방지)
- 사용자가 명시 거부한 메뉴는 추천에서 영구 제외 가능
- 데이터는 전부 로컬(IndexedDB)에서 시작. 계정은 추후.

## 7. 식사 라이프로깅 (사진 기록 & 영상 컴파일)

> **2차 가치이자 잔존 엔진**. 결정 도구의 자연스러운 후속 흐름. 강요하지 않고 옵트인.

### 흐름

```
[결정] → [식사] → [한 컷 촬영, 1탭] → [자동 메타 태깅]
                                        ↓
                              [하루/한 주 끝]
                                        ↓
                             [자동 컴파일된 영상 푸시]
                                        ↓
                          [인스타 공유 → 워터마크 유입]
```

### 진입점

1. 결과 화면 하단 액션: `🍽️ 먹고 사진 찍기`
2. 시간대 자동 알림: 점심 끝날 시간에 "오늘 점심 한 컷?" 푸시
3. 빠른 진입: 홈에서 `[빠르게 기록]` 버튼 — 결정 없이 바로 촬영

### 캡처 UX

- `getUserMedia()` 인앱 카메라 또는 시스템 카메라 (`<input capture>`) 둘 다 지원
- 1탭 촬영 → 메뉴명 자동 태깅 (방금 결정한 메뉴) → 저장 끝
- 메뉴 결정 없이 촬영한 경우 → 메뉴 검색/직접 입력
- 메타데이터: 시간, 위치(옵션), 메뉴, 카테고리, 시간대

### 영상 컴파일

- **v2.0**: 사진 + 메뉴명 슬라이드쇼 (Canvas + MediaRecorder, 9:16 / 1:1 / 16:9 export)
- **v2.1**: 음악, 트랜지션, 필터, 템플릿 (FFmpeg.wasm 또는 서버 처리)
- 트리거: 하루 마감(자정) / 주 마감(일요일 밤) / 사용자 수동

### 공유

- Web Share API (`navigator.share({ files: [...] })`) — iOS/Android 시스템 공유 시트
- 다운로드 후 인스타 수동 업로드도 지원
- 무료: 우측 하단 작은 워터마크 (`@오늘의밥`)
- 프리미엄: 워터마크 제거 + 고급 템플릿/음악

| `--accent` | `#FF9500` (iOS Orange) | `#FF9F0A` (iOS Orange Dark) |
| `--success` | `#34C759` | `#30D158` |
| `--destructive` | `#FF3B30` | `#FF453A` |

### 타이포그래피

- **한글**: Pretendard Variable
- **영문/숫자**: SF Pro Display (시스템 폴백)
- **사이즈**: iOS HIG 따름 — Large Title 34, Title 1 28, Title 2 22, Body 17, Caption 13
- **줄높이**: 1.2~1.4
- **자간**: 한글 -0.02em, 영문 0

### 컴포넌트 원칙

- **모달 → 시트**: 모바일은 바텀시트, 데스크톱은 사이드 인스펙터
- **그림자 최소화**: 보더 + 미세한 톤 차이로 깊이 표현
- **라운드**: 12px (작은 요소), 16px (카드), 20px (시트)
- **버튼**: 채움 버튼 1개 + 텍스트 버튼 = 명확한 우선순위
- **이모지**: 헤드라인/버튼에서 제거. 메뉴 카테고리 표시에만 최소 사용
- **모션**: 스프링 이징 (`cubic-bezier(0.32, 0.72, 0, 1)`), 200~400ms
- **햅틱**: `navigator.vibrate(10)` 결정 순간/촬영 순간에 짧게

### 영상/카메라 UI

- 카메라 시트: 풀스크린, 검정 배경, 큰 셔터(72pt), 우상단 닫기, 좌하단 갤러리 진입
- 영상 결과물 프리뷰: iOS Photos 스타일 — 검정 배경 + 화이트 컨트롤
- 영상 템플릿은 **무지+타이포** 기반이 디폴트 (이모지/스티커 과한 것 금지)

### 다크모드

1급 시민. `prefers-color-scheme` 자동 감지 + 사용자 수동 토글 (system/light/dark 3택).

## 9. 정보 구조 / 화면

```
/                      Home — 시간대 자동 인식 헤드라인, 모드 선택, 카테고리 필터
                       하단 액션: [빠르게 기록] (라이프로깅 즉시 진입)

/decide/quick          Quick 모드
```

## 10. 기술 스택

| 영역 | 선택 |
|---|---|
| 프레임워크 | **Vue 3** (Composition API + `<script setup>`) |
| 빌드 | Vite |
| 언어 | TypeScript |
| 상태 | Pinia |
| 라우팅 | Vue Router 4 |
| 스타일 | Tailwind CSS (커스텀 토큰) + CSS 변수 (다크모드) |
| 폰트 | Pretendard (자체 호스팅) |
| 저장소 | **IndexedDB** (v2.0부터 — 사진 Blob 저장 필요) |
| 카메라 | `getUserMedia()` + `<input capture>` 폴백 |
| 영상 | Canvas + MediaRecorder API (v2.0) → FFmpeg.wasm / 서버 (v2.1+) |
| 공유 | Web Share API + `canShare({ files })` |
| PWA | manifest + service worker (v2.0부터 — 푸시/홈화면 설치) |
| 배포 | Vercel (현재 vercel.json 유지) |

**의도적 미선택**:
- 백엔드 — 익명 로컬 우선, 계정/클라우드 백업은 사용자 확보 후 (v2.2+)
- 컴포넌트 라이브러리 — Apple 톤을 직접 구현하는 게 핵심 차별점
- 네이티브 앱 — 웹+PWA로 충분, 진입 마찰 ↓

## 11. 데이터 모델 (요약)

```ts
type Menu = {
  id: string
  name: string
  category: '한식' | '일식' | '중식' | '양식' | '분식' | '아시안' | '기타'
  tags: string[]                  // 따뜻한, 매운맛, 면, 국물, 해장, 야식 등
  fitness: {
    time: { breakfast: number; lunch: number; dinner: number; latenight: number }
    dayOfWeek: { weekday: number; weekend: number }
    weather: { cold: number; hot: number; rainy: number }
  }
}

type DecisionEntry = {
  id: string
  menuId: string
  timestamp: string
  outcome: 'eaten' | 'passed' | 'unknown'
  mode: 'quick' | 'tournament' | 'slot'
  mealType: 'breakfast' | 'lunch' | 'dinner' | 'latenight' | 'brunch'
}

type MealPhoto = {
  id: string
  menuId?: string                 // 결정 흐름에서 온 경우 연결, 즉석 기록은 옵션
  menuName: string                // 캐싱 (메뉴 데이터 변경 대응)
  imageBlob: Blob                 // IndexedDB 저장
  thumbnailBlob: Blob             // 리스트용
  takenAt: string
  location?: { lat: number; lng: number; placeName?: string }
  mealType: 'breakfast' | 'lunch' | 'dinner' | 'latenight' | 'brunch'
  note?: string
}

type Reel = {
  id: string
  range: { from: string; to: string }  // 하루 또는 한 주
  photoIds: string[]
  template: string                // 템플릿 ID
  aspect: '9:16' | '1:1' | '16:9'
  videoBlob?: Blob                // 생성 후 캐싱
  createdAt: string
}

type ResultAction = {
  type: 'mealkit' | 'map' | 'delivery' | 'capture' | 'sponsor'
  label: string
  url?: string                    // 외부 URL (어필리에이트/딥링크)
  route?: string                  // 내부 라우트 (예: /capture)
  trackingId?: string
}

type Preferences = {
  excludedMenuIds: string[]
  preferredCategories: string[]
  avoidanceWindowDays: number     // 기본 3
  theme: 'system' | 'light' | 'dark'
  locationEnabled: boolean
  notificationsEnabled: boolean
  reelAutoGenerate: 'daily' | 'weekly' | 'manual'
  premium: boolean                // 워터마크 제거 등
}
```

메뉴 데이터는 30개 → **80~100개**로 확장. 시간대별 균형 잡기 (아침/야식 풀 보강).

## 12. 출시 범위

### v2.0 (1차 출시 — 2~3주 목표)

**결정 도구 (1차 가치)**:
- [ ] Vue 프로젝트 셋업 (Vite + TS + Tailwind + Pinia + Router)
- [ ] 디자인 토큰 + 다크모드 인프라
- [ ] 메뉴 데이터 확장 (80~100개, 시간대별 균형)
- [ ] 3가지 결정 모드 (Quick / Tournament / Slot)
- [ ] 시간대 자동 인식 + 컨텍스트 가중치 추천 엔진
- [ ] 결과 화면 외부 액션 슬롯 (`ResultAction[]` 인프라 — 어필리에이트/딥링크 즉시 교체 가능)
- [ ] 결정 히스토리 + 카테고리 통계

**라이프로깅 (2차 가치 — 최소 기능)**:

## 13. 수익화 로드맵

**원칙**: 컨셉(결정 도구 + 라이프로깅)을 훼손하지 않는 수익만. 의사결정 흐름 직후의 "다음 행동"과 라이프로깅 결과물 자체를 자연스럽게 수익화한다.

### 한국 시장 어필리에이트 현실

| 채널 | 사용 가능 | 비고 |
|---|---|---|
| 쿠팡파트너스 | ✅ 즉시 | 누구나 가입, 카테고리 3%~ 수수료. 밀키트/식자재 핵심 |
| 마켓컬리 파트너스 | ✅ 즉시 | 프리미엄 신선식품 |
| 링크프라이스 / 애드픽 | ✅ 즉시 | 통합 어필리에이트 (11번가, SSG, 롯데 등 한 번에) |
| 배달의민족 / 요기요 | ❌ 없음 | 공개 어필리에이트 없음. 딥링크는 가능하지만 수익 0 |
| 카카오맵 / 네이버지도 | ❌ 어필리에이트 아님 | UX 가치만 있음 (수익 0) |
| 카카오 애드핏 / AdSense | ✅ 디스플레이 광고 | 트래픽 의존, DAU 1000+ 권장 |

### 단계적 수익화

| 단계 | 시점 | 액션 | 예상 매출 |
|---|---|---|---|
| **Phase 0** | v2.0 출시 | 외부 액션 슬롯 + 영상 워터마크 인프라만 확보. 수익 0 | 0 |
| **Phase A** | DAU 100+ | 쿠팡파트너스 + 마켓컬리 + 링크프라이스 어필 활성화 | 월 1~15만원 |
| **Phase B** | DAU 1000+ | 결과 화면 하단 비침습 광고 (카카오 애드핏/AdSense) | 월 5~30만원 추가 |
| **Phase C** | DAU 5000+ | 프리미엄 구독 도입 (워터마크 제거 + 고급 템플릿 + 광고 제거) | 전환율 1~3%, 월 50만~수백만 |
| **Phase D** | DAU 10000+ | B2B 사내 점심봇 패키지, 트렌드 데이터 판매, 인플루언서 시드 | 별도 영업 |

### 외부 액션 슬롯 (v2.0 인프라)

결과 화면 하단에 항상 액션 묶음 노출. v2.0은 딥링크 + 라이프로깅 진입만, v2.1에서 어필리에이트 링크 주입:

```
[결정된 메뉴: 김치찌개]

  ┌─ 🍽️ 먹고 사진 찍기  → /capture (라이프로깅 진입 — 잔존 엔진)
  ├─ 🛒 집에서 만들기   → 쿠팡/마켓컬리 밀키트 (어필리에이트 - 수익)
  ├─ 🗺️ 근처 식당       → 카카오맵 딥링크 (수익 0, UX 가치)
  └─ 🛵 배달 주문       → 배민 딥링크 (수익 0, UX 가치)
```

### 라이프로깅 수익 경로 (식사일지와 다른 점)

| 경로 | 수익화 메커니즘 |
|---|---|
| 영상 공유 워터마크 | 인스타 공유 → 자연 신규 유입 (사용자 획득 비용 ↓) |
| 프리미엄 구독 | 결과물에 감정 투자 후 결제 동기 — 1 Second Everyday 모델 |
| 메뉴 상세 페이지 SEO | 자연 검색 유입 → 어필리에이트 깔때기 |
| 누적 사진/메뉴 데이터 | 광고 타깃팅 정밀도 ↑ (v2.2+ 백엔드 시점) |
| 인플루언서 시드 | 음식 인플루언서가 도구로 사용 → 무료 마케팅 |
