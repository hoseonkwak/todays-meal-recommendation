# 메뉴 데이터 작성 가이드 (80~100개)

> `src/data/menus.ts` 작성 시 따라야 할 스키마와 균형 가이드. `menu-data-agent`가 이 문서를 강제 참조.

---

## 스키마

```ts
type Menu = {
  id: string                    // kebab-case 영문 (예: 'kimchi-stew')
  name: string                  // 한국어 표기 (예: '김치찌개')
  category: Category
  tags: string[]                // 검색·필터·가중치 신호
  fitness: {
    time: TimeFitness
    dayOfWeek: DayOfWeekFitness
    weather: WeatherFitness
  }
}

type Category =
  | '한식' | '일식' | '중식' | '양식'
  | '분식' | '아시안' | '기타'

type TimeFitness = {
  breakfast: number    // 0.5 ~ 2.0
  brunch: number       // 0.5 ~ 2.0
  lunch: number        // 0.5 ~ 2.0
  dinner: number       // 0.5 ~ 2.0
  latenight: number    // 0.5 ~ 2.0
}

type DayOfWeekFitness = {
  weekday: number      // 0.5 ~ 2.0
  weekend: number      // 0.5 ~ 2.0
}

type WeatherFitness = {
  cold: number         // 0.5 ~ 2.0 (5도 이하)
  hot: number          // 0.5 ~ 2.0 (28도 이상)
  rainy: number        // 0.5 ~ 2.0
  // 평범한 날씨는 가중치 없음 (1.0 디폴트)
}
```

---

## 가중치 부여 원칙

### 절대 규칙

- **모든 fitness 값은 0.5 ~ 2.0 범위**. 위반 시 추천 엔진이 거부.
- 디폴트는 1.0 (영향 없음).
- 한 메뉴가 모든 시간대에서 2.0인 건 의미 없음 — **상대성**이 가중치의 본질.

### 권장 분포

대부분의 메뉴는 1.0을 기본으로 두고, 명확히 어울리는/안 어울리는 시간대만 조정:

| 가중치 | 의미 | 사용 빈도 |
|---|---|---|
| 0.5~0.7 | 매우 부적합 | 분명히 안 어울리는 경우만 |
| 0.8~0.9 | 약간 부적합 | 가끔 |
| 1.0 | 중립 | 디폴트 |
| 1.2~1.5 | 약간 적합 | 자주 |
| 1.6~2.0 | 매우 적합 | 시그니처 시간대만 |

### 예시

**김치찌개**:
- 시간대: lunch 1.5, dinner 1.5, latenight 1.0, breakfast 0.7, brunch 0.8
- 요일: weekday 1.2, weekend 1.0
- 날씨: cold 1.8, hot 0.7, rainy 1.3

**샐러드**:
- 시간대: lunch 1.5, brunch 1.5, dinner 1.0, breakfast 0.9, latenight 0.5
- 요일: weekday 1.3, weekend 1.0
- 날씨: cold 0.7, hot 1.5, rainy 1.0

**치킨**:
- 시간대: dinner 1.5, latenight 2.0, lunch 0.9, brunch 0.7, breakfast 0.5
- 요일: weekday 1.0, weekend 1.4
- 날씨: cold 1.0, hot 1.0, rainy 1.5

## 카테고리별 목표 개수 (총 80~100개)

| 카테고리 | 개수 | 비고 |
|---|---|---|
| 한식 | 25~32 | 한국 사용자 메인 (계절·날씨 시그니처 포함) |
| 일식 | 10~12 | |
| 중식 | 8~10 | |
| 양식 | 12~15 | 파스타·스테이크·버거 등 |
| 분식 | 8~10 | 떡볶이·김밥·라면 등 |
| 아시안 | 5~7 | 베트남·태국·인도 |
| 기타 | 5~8 | 샌드위치·치킨·죽 등 — 시간대 보강용 |

## 시간대별 풀 보강 (라이프로깅 시너지 위해)

각 시간대에 **최소 후보 풀 크기 확보**:

| 시간대 | 최소 적합 메뉴 수 (fitness ≥ 1.3) |
|---|---|
| breakfast | 15개 이상 |
| brunch | 15개 이상 |
| lunch | 50개 이상 (가장 큼) |
| dinner | 50개 이상 |
| latenight | 20개 이상 |

**아침 메뉴 풀**(v1 부재):
- 토스트(잼/계란), 시리얼, 죽(전복죽/야채죽), 샌드위치, 베이글, 그릭요거트, 스무디볼, 오트밀, 김밥, 컵라면, 해장국, 콩나물국밥, 북엇국, 누룽지, 미음, 김치죽, 단호박죽, 토마토 스크램블, 프렌치토스트, 팬케이크

**야식 메뉴 풀**(v1 빈약):
- 치킨, 라면(신라면/짜파게티/너구리), 떡볶이, 족발, 보쌈, 곱창, 닭발, 김밥, 컵라면, 햄버거, 피자, 핫도그, 핫바, 만두, 군만두, 마라탕, 컵떡볶이, 닭갈비, 야끼소바, 야끼우동

## 태그 가이드

`tags` 필드는 검색·필터·메뉴 상세 정보용. 일관된 어휘 사용:

### 맛·향
- 매운맛, 달콤한, 짭짤한, 시원한, 따뜻한, 담백한, 진한, 깔끔한, 구수한, 새콤한, 고소한

### 형태·구성
- 국물, 면, 밥, 빵, 튀김, 구이, 볶음, 찜, 무침, 회, 떡, 죽, 만두, 샐러드

### 재료 핵심
- 고기, 돼지, 소고기, 닭, 해산물, 생선, 채소, 두부, 계란, 치즈, 면류

### 상황
- 해장, 간편, 든든, 고급, 캐주얼, 단체, 1인

### 건강
- 건강한, 다이어트, 고단백, 저칼로리, 든든

## 작성 체크리스트

새 메뉴 추가 시:

- [ ] `id`는 kebab-case 영문이고 unique한가?
- [ ] `name`은 한국어 표기인가?
- [ ] `category`는 7개 중 하나인가?
- [ ] `tags`는 위 어휘 가이드를 따르는가?
- [ ] 모든 `fitness` 값이 0.5 ~ 2.0 범위인가?
- [ ] 시간대 가중치 중 최소 1개 이상은 1.0이 아닌가? (특성 없으면 데이터 가치 없음)
- [ ] 전체 80~100개 균형이 깨지지 않는가?

## menu-data-agent에 위임할 작업

```
@.claude/agents/menu-data-agent.md 호출

1. 80~100개 메뉴 데이터를 src/data/menus.ts로 생성
2. 카테고리별 목표 개수 준수
3. 시간대별 최소 풀 크기 준수
4. 가중치 0.5~2.0 범위 강제
5. 결과 후 카테고리·시간대 분포 통계 출력 (검증용)

  분식: 9 | 아시안: 6 | 기타: 7
  총합: 84

시간대 적합 메뉴 수 (fitness ≥ 1.3):
  breakfast: 18 ✓
  brunch: 17 ✓
  lunch: 54 ✓
  dinner: 57 ✓
  latenight: 23 ✓
```
